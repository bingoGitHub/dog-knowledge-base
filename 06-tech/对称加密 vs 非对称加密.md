## 1. 对称加密 vs 非对称加密

| 特性       | 对称加密                 | 非对称加密                |
| -------- | -------------------- | -------------------- |
| **密钥使用** | 加密和解密使用**同一个密钥**     | 使用一对密钥：**公钥**和**私钥** |
| **优点**   | **速度快**，适合加密大量数据     | **安全性高**，解决了密钥配送问题   |
| **缺点**   | **密钥配送困难**，需要安全地共享密钥 | **速度慢**，仅适合加密少量数据    |
| **常见算法** | AES、ChaCha20         | RSA、ECC              |
| **典型应用** | 文件加密、硬盘加密、大量数据传输     | 密钥交换、数字签名、身份验证       |

**核心结论**：实际应用中（如 HTTPS）通常采用**混合加密**，即用非对称加密安全地传输对称加密的密钥，再用对称加密高效处理实际数据。

## 2. AES（高级加密标准）详解

### 算法类型

对称加密算法。

### 核心参数（密钥长度）

- **AES-128**：128位（16字节），加密10轮
    
- **AES-192**：192位（24字节），加密12轮
    
- **AES-256**：256位（32字节），加密14轮（最高安全等级）
    

### 加密流程（四步操作）

1. **字节代换（SubBytes）**：通过 S 盒将每个字节替换为另一个字节，实现混淆。
    
2. **行移位（ShiftRows）**：将数据块矩阵的每一行向左循环移动，打乱排列顺序。
    
3. **列混淆（MixColumns）**：对每一列进行数学混合，将信息扩散到整个列。
    
4. **轮密钥加（AddRoundKey）**：将当前状态与这一轮的专用密钥进行异或操作，注入密钥。
    

> **注意**：最后一轮加密会省略“列混淆”步骤。

### 密钥扩展

将原始的 AES 密钥通过复杂过程生成多个轮密钥（11、13 或 15 个），确保每一轮加密使用不同的密钥。

### 工作模式

- **ECB（电子密码本模式）**：最简单，但相同的明文块生成相同的密文块，安全性较弱，**不推荐使用**。
    
- **CBC（密码分组链接模式）**：加密前每个明文块与前一个密文块异或，需要**初始化向量（IV）**，安全性更高。
    
- **CTR（计数器模式）**：将块密码转为流密码，支持并行计算，性能优秀。
    

### 填充（Padding）

当数据长度不是 16 字节的整数倍时，需要填充。最常见的是 **PKCS#5/PKCS#7** 标准：缺少几个字节就补上值为几的几个字节。

## 3. RSA 算法详解

### 算法类型

非对称加密算法。

### 安全基础

基于**大整数分解**的数学难题：将两个大素数相乘非常简单，但将乘积分解回两个素数极其困难。目前推荐使用 **2048位** 或更高长度的密钥。

### 密钥生成过程

1. 随机选择两个大素数 **p** 和 **q**（严格保密）。
    
2. 计算乘积 **n = p × q**（**n** 是密钥的一部分，其长度即为 RSA 密钥长度）。
    
3. 计算欧拉函数 **φ(n) = (p-1)(q-1)**（保密）。
    
4. 选择一个与 φ(n) 互质的整数 **e** 作为公钥指数（常用 65537）。
    
5. 计算私钥指数 **d**，满足 **e × d ≡ 1 (mod φ(n))**。
    
6. 最终：**公钥是 (n, e)**，**私钥是 (n, d)**。素数 p 和 q 需安全销毁。
    

### 加密与解密

- **加密（公钥操作）**：**C ≡ M^e (mod n)**
    
- **解密（私钥操作）**：**M ≡ C^d (mod n)**
    

### 主要应用

- **安全传输对称密钥**：在 HTTPS 握手中，用 RSA 加密临时生成的 AES 密钥并发送给对方。
    
- **数字签名**：用私钥对信息的哈希值进行签名，他人可用公钥验证签名的真实性和信息的完整性。

## 4. HTTPS 中 AES 和 RSA 的配合

在 HTTPS 的 TLS 握手中，AES 和 RSA 通过**混合加密**方式协作，主要有两种模式：

### 方式一：传统 RSA 密钥交换

1. **身份核实**：服务器发送包含 RSA 公钥的数字证书给客户端。
    
2. **生成并加密密钥**：客户端验证证书后，生成一个临时的 AES 会话密钥，用服务器的 RSA 公钥加密后发送给服务器。
    
3. **安全获取密钥**：服务器用自己的 RSA 私钥解密，得到 AES 会话密钥。
    
4. **高效通信**：双方使用这把 AES 密钥对所有后续数据进行对称加密通信。
    

> **缺点**：**不具备完美前向保密**。如果服务器之后泄露了 RSA 私钥，黑客可以解密所有历史记录的数据。

### 方式二：现代主流 ECDHE 密钥交换

1. **身份核实**：服务器发送包含 RSA 公钥的数字证书。
    
2. **公开临时密钥**：服务器额外生成一个临时的公钥（用于 ECDHE），并用 RSA 私钥对这个临时公钥进行**签名**，以证明其真实性。
    
3. **各自计算共享密钥**：
    
    - 客户端验证签名后，生成自己的临时公钥发给服务器。
        
    - 双方使用各自的临时私钥和对方的临时公钥，通过 ECDHE 算法独立计算出完全相同的**共享秘密**。
        
4. **生成会话密钥**：双方用这个共享秘密结合随机数，共同生成 AES 会话密钥。
    
5. **高效通信**：使用 AES 密钥进行数据加密通信。
    

> **优点**：**具备完美前向保密**。即使之后 RSA 私钥泄露，黑客也无法解密之前的数据，因为 AES 会话密钥是临时生成的且从未在网络中传输。

### 核心分工总结

- **AES**：**负责实际的数据加密**。速度快，适合加密海量的网页内容。
    
- **RSA**：**负责身份验证和密钥协商**。在传统模式中直接加密传输 AES 密钥；在现代模式中为临时密钥提供签名验证，确保通信方的真实性。
    

最终，客户端和服务器会结合**客户端随机数、服务器随机数**以及交换得来的**共享密钥**，通过伪随机函数生成最终的 AES 会话密钥，用于后续的加密通信。
